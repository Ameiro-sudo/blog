审查日期:2026-10-02

采集规模:本地构建产物 120 个配置 + 线上部署 80 个配置 = 页面 × (移动 390 / 平板 820 / 桌面 1440) × (浅色 / 深色)

## 方法说明

对比度不是用计算样式推算的。审查脚本先注入 `*,*::before,*::after{color:transparent}` 把整页文字擦掉再截一张图,然后采样每个文字位置的真实像素作为底色 —— 毛玻璃、渐变、`backdrop-filter`、背景照片全部算进真实底色,再用 WCAG 相对亮度公式算比值。所以下面出现的 `#2f6a84 on #90424f` 这类数字,是照片上的真实取色,不是纸面推算。

需要说明的局限:

- **渐变文字未量化**。`background-clip:text` 的元素(如导航站 logo「SnowBlock」)无法用单一前景色计算,被跳过,只有目视判断 —— 导航站 logo 是金褐色渐变压在浅色卡片上,目测偏低。
- **整页长截图对 fixed 背景层有拼接伪影**。超过一屏的页面我另外用视口分屏截图复核,结论以分屏截图为准。
- **雪花 canvas 在采图中被关闭**(保证可复现)。历史截图 `blog/.visual-check/home-light.png` 显示它平时正常渲染。

## P0 — 影响可用性,建议优先修

### 1. 博客在 ≤600px 完全无法导航

`assets/css/style.css:799-820` 的折叠规则把 `.nav-links` 在 ≤600px 变成绝对定位 + `max-height:0` + `opacity:0` 的抽屉,靠 `.topbar-menu` 按钮和 `.nav-links.open` 打开。**但 `app.vue` 里既没有 `.topbar-menu` 这个元素,也没有切换 `.open` 的任何处理** —— 这是 Vanilla JS SPA 时代的遗留 CSS,Nuxt 迁移时组件没跟上。

实测:

| 视口 | `.nav-links` | 渲染高度 | opacity | 汉堡按钮 |
|---|---|---|---|---|
| 390px | absolute | **1px** | 0 | **不存在** |
| 600px | absolute | **1px** | 0 | **不存在** |
| 601px | static | 49px | 1 | 不存在 |

移动端用户无法到达 文章 / 归档 / 相册 / 说说 / 友链 / 关于 任何分区,只能靠页面内的「全部文章」之类的正文链接或直接改地址栏。

修复方向:在 `app.vue` 的 `.top-bar-inner` 里补回汉堡按钮并接上 `.open` 切换;或者把这段折叠规则的断点调整到导航真的放不下的宽度。

### 2. 博客约 1/4 的线上访问整站没有图标

`nuxt.config.ts:66` 用 `media="print"` 挂 Font Awesome,`:79` 在 `bodyClose` 挂 `load` 监听把它切成 `all`。**如果样式表在 bodyClose 脚本执行前就加载完了,`load` 事件已经触发过,监听器永远等不到,`media` 永久停在 `print`** —— 全站图标字体不生效。

失败率实测(每次都是全新 context):

| 目标 | 失败 / 总数 | 失败时表现 |
|---|---|---|
| 本地 首页 | **8 / 8** | `media=print`,14 个图标元素全部 `content:none`、0×0 |
| 本地 文章列表 | 4 / 8 | 10 个图标全失 |
| **线上 首页** | **2 / 8** | 14 个图标全失 |

线上一半左右的访问会看到:导航项没有图标、社交按钮是空心圆、主题切换是个空方块、回到顶部没有箭头。另外两个静态站是普通阻塞 `<link>`,不受影响。

修复方向:换成 `<link ... onload="this.media='all'">` 内联属性,或在 bodyClose 脚本里补一次「若 `link.sheet` 已存在则立即切 `all`」的兜底判断。

### 3. MC 状态站 5 个页面缺全局 reset,移动端横向溢出

全站只有 `index.html:46` 和 `404.html:20` 有 `*{margin:0;padding:0;box-sizing:border-box}`。`login.html`、`admin.html`、`view-logs.html`、`api-management.html`、`player-history-chart.html` 都没有,于是 `box-sizing` 退回 `content-box`,body 还带着浏览器默认的 `8px` margin。

实测盒子模型(390px 视口):

```
.login-container   width:100%  max-width:400px  box-sizing:content-box
                  → 实际 402px,left=24,right=426
.form-group input  width:100%  → 368px,right=422   ← 落在视口外
documentElement.scrollWidth = 426  (视口 390,溢出 36px)
```

登录表单的输入框右边缘被切在视口外,必须横向滚动才能看全。受影响页面:登录 / 管理面板 / API日志 / API管理(历史图表因为容器宽度不同侥幸没溢出)。360px 视口下溢出同样存在。

## P1 — 明显影响可读性

### 4. 博客浅色主题下代码块几乎不可读(单页 416 处对比度不达标)

`style.css:492` 的 `.hljs { background: transparent; }` 把 atom-one-dark 的深色底剥掉了,但 token 配色还是深色主题那一套;而 `<pre>` 用的是 `var(--body-overlay)`,浅色主题下等于 `rgba(255,255,255,0.15)`,实际就是白底。

| token | 浅色实测 | 需要 | 深色实测 |
|---|---|---|---|
| `hljs-built_in` `#e6c07b` | **1.67:1** | 4.5:1 | 通过 |
| `hljs-string` `#98c379` | **1.95:1** | 4.5:1 | 通过 |
| `hljs-attr` `#d19a66` | **2.38:1** | 4.5:1 | 通过 |

`/posts/post1/` 一页浅色主题 416 处不达标,深色主题只有 12 处。全站对比度统计:

| 站点 | 浅色不达标 | 深色不达标 |
|---|---|---|
| 博客 | **544 / 1985 = 27.4%** | 29 / 1964 = **1.5%** |
| MC 状态站 | 41 / 195 = 21.0% | 29 / 195 = **14.9%** |
| 导航站 | 3 / 51 = 5.9% | 3 / 51 = 5.9% |

修复方向:最省事的是让 `<pre>` 在两种主题下都用深色底(`#0d1117`),和代码配色配套;或者补一套浅色 highlight 主题。

### 5. MC 状态站与导航站的「深色模式」其实不暗

`html.dark --body-overlay` 只有 `rgba(0,0,0,0.30)`,压在高亮照片上实测背景相对亮度仍有 **0.28**(浅色主题是 0.68)。而深色主题的标题色是浅蓝 `#8fd8ef`,落在照片亮部:

- MC 站 `<h1>`「Minecraft 服务器」浅蓝压在照片上 **1.34:1**,最差 **1.97:1**(需 3:1)
- 浅色主题同一个标题深蓝 `#2f6a84` 最差 **1.14:1**
- `p.sub` 小字(11.2px)最差 **1.05:1**

对照博客:深色主题背景相对亮度 **0.010–0.016**,是真的暗 —— 因为它的内容都坐在不透明毛玻璃卡上,照片只从卡片缝隙露出。MC 站和导航站则是让文字直接压在照片上。

修复方向:把这两站的 `html.dark --body-overlay` 加深(0.30 → 0.55 以上),或给页头文字加一层 scrim,让标题不必直接压在照片上。

### 6. 博客首页没有 `<h1>`

实测标题层级只有 `["H3 \"Bocchi Client:从原版模板一步一步来的改\""]` —— 既没有 `h1`,而且直接从 `h3` 起步。其余页面都正常(文章列表 `H1 雪地笔记`、状态站 `H1 Minecraft 服务器`、导航站 `H1 SnowBlock`)。

### 7. 博客 601–760px 顶栏高度突变

| 视口 | 顶栏高度 | 导航 |
|---|---|---|
| 600px | 55px | 塌陷不可见 |
| 601px | **89px** | 换到第二行 |
| 680px | **98px** | 换到第二行 |
| 760px | 55px | 回到第一行 |

和 P0-1 叠加后,移动端到小平板这一段的顶栏表现很不稳定。

## P2 — 打磨项

8. **相册封面 `alb-01.webp` 源图倒置 180°。** 它同时是相册封面、相册详情首图和首页照片墙的第一张,所以首页就挂着这张倒置的图。抽查 `alb-02`、`alb-05` 方向正常,是单张数据问题,重新导出即可。

9. **相册封面被拉伸。** `alb-01` 原始 500×900(比例 0.556),渲染成 283×461(比例 0.614),`object-fit: fill` 没有保持原始比例。

10. **点击区域偏小。** 博客 `.site-name` 高 22–23px、MC 站「返回主页」高 17px,低于 WCAG 2.5.8 的 24×24。

11. **焦点样式缺失。** 博客文章列表搜索框、`上一页` 按钮、归档页年份按钮,focus 前后 computed 样式完全无变化,键盘用户看不出焦点在哪。

12. **两站 404 页返回按钮对比度不足。** `a.nf-home` 白字压在 `#8fd8ef` 上:深色主题 **1.59:1**、浅色主题 3.09:1(需 4.5:1)。

13. **导航站没有主题切换入口。** 它读 `localStorage.theme` 和 `prefers-color-scheme`,但页面里没有切换按钮,用户被锁死在系统偏好。另外两站都有开关。

14. **博客首页次级文章卡片文字直接压在封面图上**,没有渐变蒙版:标题最差 **1.67:1**、日期最差 **1.97:1**。

15. **MC 状态站首页下半屏大面积留白。** 内容只占视口上方约 45%,其余全是照片,视觉上像没加载完。

## 确认没问题的部分

- **设计 token 无漂移。** 三站 `tokens.css` 字节级完全相同(MD5 `198CEAE8`,7699 bytes / 212 行),色彩、圆角、字体、动效 token 全部一致。
- **本地构建与线上部署无差异。** 对比度统计逐项吻合(博客浅色 27.4% vs 27.7%、深色 1.5% vs 1.5%;状态站 21.0% vs 21.5%),gh-pages 与本地 main 同步,没有「改了没上线」的情况。
- **404 页行为正确。** 三站对不存在的路径都返回 HTTP 404 并显示品牌化文案(「被末影人叼走了」「这里什么都没有，除了雪」),标题也各自正确。
- **`prefers-reduced-motion` 三站都实现了。** 开启后雪花 canvas 正确 `display:none`,各有 2–3 条对应媒体查询。
- **横向溢出仅限上述 MC 站 5 个页面。** 博客和导航站在三个断点下 `scrollWidth == innerWidth`。
- **无意外的控制台报错。** 只有 404 页的预期路由报错和导航站 2 个中止的外链探测请求。

> 审查中出现过一次 `blog/friends` 返回 404 的记录,复测 5 次均 200,`friends/index.html`(8373 bytes)存在 —— 是本地静态服务器的一瞬时抖动,不是站点问题。

## 建议的处理顺序

1. 博客移动端导航(P0-1)—— 影响面最大,一次改动恢复六个分区入口
2. 博客 Font Awesome 竞态(P0-2)—— 一行内联属性即可根治
3. MC 站 5 个页面补 reset(P0-3)—— 复制 `index.html:46` 那行过去
4. 博客代码块底色(P1-4)—— 改一处 `<pre>` 背景,消掉全站 27% 的浅色对比度问题里的大头
5. MC 站 / 导航站深色蒙版加深(P1-5)—— 改两个 token 值
6. 其余 P1/P2 按站点排期
