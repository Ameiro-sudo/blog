## 1. 项目概览

零后端静态博客,Nuxt 3 静态生成(SSG),Markdown 写作,GitHub Pages 托管,Cloudflare CDN 加速。

- **渲染**:Nuxt 3 SSG(`ssr: true` + `nitro.preset: static`),真实路由 `/posts/<id>/`;Markdown 在**构建期**由 `scripts/build.js` 用 markdown-it 14 渲染并经 sanitize-html 白名单消毒,产出 HTML payload,前端零运行时 Markdown 解析
- **构建**:`npm run build` = 内容索引(`scripts/build.js`)→ `nuxt generate` → `scripts/copy-static.js` 把 `assets/` 并入产物
- **部署**:GitHub Actions 自动构建 → 推 `gh-pages` 分支 → GitHub Pages(源 = gh-pages 分支)
- **零外部运行时依赖**:JS/CSS/字体/图标全部在仓库内(头像与一言 API 均已本地化)

> **历史提醒**:2026-08-22 之前本站是 Vanilla JS 单页 SPA(hash 路由,`assets/js/*` + 根 `index.html`)。
> 迁移后的 Nuxt 版本已上线。**那套旧文件已于 2026-10-01 从源码树彻底删除**(§10.2/§10.3 已办结):

## 3. 构建系统

`npm run build` 依次执行三步:

**① `node scripts/build.js`(内容管线)**

1. **文章索引**:解析 `content/posts/*.md` 的 front matter(YAML)→ 生成 `content/posts/index.json`(id/标题/日期/标签/置顶/封面/摘要)
2. **文章 payload**:把正文 markdown 渲染为 HTML(markdown-it + highlight.js 代码高亮 → `enhanceArticleHtml` 补 `code-block-wrapper`/`copy-btn`/懒加载图 → `sanitizeArticleHtml` 白名单消毒),写入 `content/posts/<id>.json`;关于页同理(`content/pages/about.json`)
3. **相册索引**:自动扫描本地 `assets/vendor/images/albums/` 平铺图片生成 `content/albums/index.json`(单相册,封面取第一张,EXIF 自动读取);可选 `meta.json`(title/description/date)放在该目录下控制相册元数据。预留远程接入接口:在 `site.config.json` 配置 `albumsSource`(远程 JSON 地址)后,构建改为从该地址拉取相册数据
4. **RSS / sitemap / robots**:从索引生成 **`public/feed.xml`、`public/sitemap.xml`、`public/robots.txt`**(真实路由 URL,如 `/posts/post8/`;三者的绝对地址都取自 `site.config.json` 的 `SITE_URL`)
5. **配置注入**:读取 `site.config.json`,注入文章 payload 等处需要的站点信息

**② `nuxt generate`(SSG)**

- 预渲染路由:`nuxt.config.ts` 显式展开 `content/posts/index.json` 的每篇文章(`/posts/<id>`)+ `/`、`/posts`,其余页面靠 `crawlLinks` 爬取
- 每个页面产出 `index.html`(SEO/首屏)+ `_payload.json`(客户端导航用)
- `failOnError: false`:单篇文章预渲染失败不会让整站构建失败,但日志里可见

**③ `node scripts/copy-static.js`(静态资源并入)**

- 把 `assets/` 整体复制进 `.output/public/assets/`(CSS/图片/字体按原 URL 提供,不做 Vite 处理 → 视觉零回归)
- 这一步曾带一份「死资源剪枝清单」(旧 SPA 运行时等 5 项、约 395KB),用来在源码还没删干净时拦着它们不上线;2026-10-01 源码侧已彻底删除,清单与引用扫描一并移除(见 §10)。若将来又引入无人引用的资源,靠 code review 发现即可

**幂等**:内容无变化时 `build.js` 不会改文件;CI 里 `git diff` 无变更则不会产生构建提交。

**站点配置**:改头像/昵称/链接/站点地址等只需编辑 `site.config.json`,再 `npm run build`。

> **2026-10-02 起这句话才真正成立**:此前站点地址在 `nuxt.config.ts`、`pages/posts/[id].vue`、
> `pages/gallery/[album].vue`、`public/robots.txt` 里各硬编码了一份,只改 `site.config.json`
> 的话 og/twitter/canonical 会集体指向旧域名。现在全部改为引用 `SITE_URL` 与 `ogDefaults`,
> `robots.txt` 也由 `build.js` 生成。**新增页面时别再写死域名**。

**Windows 注意事项**:
- 构建在 Linux(CI)与 Windows(本地)的路径/行尾行为不同;`build.js` 已用 `path.basename()` 修复 Windows 路径 bug
- 本地 build 产物 hash 与 CI 不同是正常的(CRLF vs LF)
- 产物目录 `.output/`、`.nuxt/`、`.data/` 已 gitignore,不要提交

## 4. CI/CD 流程(`.github/workflows/ci.yml`)

触发:push 到 main、PR、手动 dispatch。

步骤:
1. Checkout
2. Setup Node(node 版本读 `.nvmrc` = 22,npm 缓存)
3. `npm ci`
4. `npm run build`(内容索引 → Nuxt SSG → 静态资源并入)
5. **部署**:`peaceiris/actions-gh-pages@v4`,发布目录 **`.output/public`**,`force_orphan: true` 推 gh-pages 分支
6. **Lighthouse**:`npx lhci collect --config=./scripts/lighthouserc.cjs`(`staticDistDir: .output/public`,纯报告**无断言不阻塞**),`upload-artifact` 上传(注意 `include-hidden-files: true`,因为 `.lighthouseci` 是隐藏目录)

**部署拓扑**:
```
push main → CI 构建 → force push gh-pages(.output/public) → GitHub Pages(源 = gh-pages) → CF 缓存
```

**GitHub Pages 配置**:仓库 Settings → Pages → Source: **Deploy from a branch → gh-pages / /(root)**。不要改回 main。

**CI 踩坑史**(勿回退):
- Lighthouse 断言(preset error 级 color-contrast 等)曾导致 CI 频繁失败 → 已改为纯 collect 无断言
- `lhci upload`(filesystem)会清空 collect 临时目录 → 只用 collect
- upload-artifact 默认忽略隐藏目录 → 必须 `include-hidden-files: true`
- 直接 `git push HEAD:gh-pages` 权限问题 → 改用 peaceiris action
- 迁移到 Nuxt 后,**必须发布 `.output/public` 而不是仓库根目录**;老站点的 `assets/js`、根 `index.html`、hash 路由版 sitemap 都不能再上线
- 老访客浏览器里装过旧版 Service Worker,会拿缓存挡住新站 → `public/sw.js` 是**自注销 shim**(install 后 unregister + 清空所有缓存 + 刷新页面),保留一段时间再从 `public/` 删除;不要提前删,也不要再给站点注册 SW

## 5. 文章写作

文件:`content/posts/postN.md`(新建请用 `post8.md` 递增命名)。

Front matter 格式(注意:**标题用 `# ` 一级标题写在文件首行**,build.js 和前端 stripFrontMatter 都依赖它):

```markdown
# 文章标题
date: 2026-08-05
tags: 标签1, 标签2
time: 21:00
readTime: 8 分钟
pinned: false
image: assets/vendor/images/posts/cover-xxx.webp   # 可选,封面图
---

正文 markdown...
```

**发布流程**:
1. 写文章 md
2. 本地 `npm run build` 验证:索引/payload 正常、Nuxt 预渲染无报错、`copy-static` 无 WARNING
3. `git add` 文章 + 构建产物(`content/posts/index.json`、`content/posts/<id>.json`、`public/feed.xml`、`public/sitemap.xml`、`public/robots.txt`),`git commit`,`git push` — CI 自动部署
4. 线上约 2-4 分钟生效(CF 缓存 HTML 为 DYNAMIC 不缓存) — 文章 URL 形如 `https://blog.snowblock.top/posts/post8/`

**文章内容规范**:
- 图片放 `assets/vendor/images/posts/`,正文用相对路径 `assets/...`(payload 渲染时保留此类相对图片)
- 正文新汉字**不需要**重新子集化字体(正文不用标题字体,详见 §8);但**标题**会带新字,发布前跑一次 `python scripts/font-coverage-check.py`
- 文章列表分页是按钮不是链接,新文章必须出现在 `content/posts/index.json` 中,`nuxt.config.ts` 才能把它的路由预渲染出来

## 8. 标题字体(ZCOOL KuaiLe)

`assets/vendor/fonts/files/ZCOOL_KuaiLe.woff2`(92KB,949 个字形)是 ZCOOL KuaiLe 的子集,通过 `assets/vendor/fonts/ZCOOL_KuaiLe.css` 全局声明 `@font-face`;`tokens.css` 的 `--font-title` 指向它。导航站(snowblock.top)用的是同一个字体文件(MD5 一致),改子集时两站都要同步。

**它用在哪些元素上(2026-09-12 修正)**:改样式后以 CSS 里 `font-family: var(--font-title)` 的规则为准,当前是:

| 选择器 | 位置 | 说明 |
| --- | --- | --- |
| `.site-name` | `style.css:31` | 顶栏站点名「SnowBlock」 |
| `.page-header h1` | `style.css:181` | 文章列表页主标题「雪地笔记」 |
| `.article-title` | `style.css:430` | 文章正文大标题 / 关于页 / 404 页标题 |
| `.gallery-header h1` | `style.css:667` | 相册页主标题「照片墙」 |
| `.module-header h1` | `style.css:887` | 说说 / 友链页主标题 |
| `.loader-text-frost` | `shell.css:201`(+ `nuxt.config.ts` 关键内联样式) | 加载层文案「正在连接雪境」 |

> **踩坑史(勿回退)**:Nuxt 迁移时这几个标题都被写成了 `--font-serif`,ZCOOL 只剩加载层在用,于是字体形同虚设。2026-09-12 已按上表接回;正文、卡片标题(`.post-title`)、面板标题(`.home-panel-title`)、导航项仍走 `--font-sans`/`--font-serif`,是有意为之 —— 刻意保留的对比:页面主标题用圆润手写的 ZCOOL,正文小标题(`.article-content h2/h3`)用宋体。

**覆盖自检**:`scripts/font-coverage-check.py` 自动完成「找消费者 → 从**构建产物** `.output/public` 抓取这些元素真实渲染出的文案 → 与 woff2 cmap 比对」,emoji 码位会被忽略(任何文本字体都不含,按设计回退到 emoji 字体):

```bash
python scripts/font-coverage-check.py
# [font-check] PASS - every title-font character is inside the subset (949 glyphs)
```

**什么时候要重新子集化**:新增文章后标题可能带进新汉字,跑一次上面的脚本;若报 `FAIL` 列出缺字,再按下面重建。**正文新汉字不需要**,正文不用这个字体。

重建两步(先由自检工具导出「全部标题文案」,再按该文案切子集,避免手抄字符串出错):

```bash
pip install fonttools brotli
# ① 导出所有 var(--font-title) 元素实际渲染出的文案
python - <<'PY'
import io, glob, os, re, sys
sys.path.insert(0, 'scripts')
import importlib.util
spec = importlib.util.spec_from_file_location('fc', 'scripts/font-coverage-check.py')
fc = importlib.util.module_from_spec(spec); spec.loader.exec_module(fc)
targets = [fc.target_of(s) for s in fc.selectors_using_title_font(
    ''.join(io.open(p, encoding='utf-8').read() for p in glob.glob('assets/css/*.css')))]
files = glob.glob(os.path.join(fc.OUTPUT, '**', '*.html'), recursive=True)
chars = ''.join(sorted({c for _, line in fc.collect(files, targets) for c in line}))
io.open('.subset-text.txt', 'w', encoding='utf-8').write(chars)
print(len(chars), 'characters -> .subset-text.txt')
PY

# ② 按该文案重建 woff2(只裁字形,不改字形数据)
python -m fontTools.subset assets/vendor/fonts/files/ZCOOL_KuaiLe.woff2 \
  --text-file=.subset-text.txt --flavor=woff2 --layout-features='*' \
  --output-file=assets/vendor/fonts/files/ZCOOL_KuaiLe.woff2

python scripts/font-coverage-check.py   # 回来确认 PASS
rm .subset-text.txt
```

> 上游全量字体(1.5MB TTF)来自 Google Fonts 的 `ofl/zcoolkuaile/ZCOOLKuaiLe-Regular.ttf`;当前子集(949 字形)已覆盖全站标题文案,**实测无需重建**。导航站用同一字体文件,重建后要把 woff2 同步过去。

**排版回归检查**:`node scripts/visual-check.cjs`(需先另开一窗 `node scripts/serve-dist.cjs`)在无头浏览器里逐页取标题元素,断言 computed `font-family` 首项是 `ZCOOL KuaiLe`、且没有横向溢出,同时把浅色/深色截图写到 `.visual-check/`(已 gitignore)。

浏览器按 `CHROME_EXE` → playwright-core 自带注册表 → **系统已装的 Chrome / Edge / Brave** → 扫描 ms-playwright 缓存 的顺序解析,无需任何环境变量。**不要用缓存里的 `chromium_headless_shell-*`**:那是精简构建,用普通 `executablePath` 驱动会在启动时崩(`Invalid file descriptor to ICU data received`,退出码 `0x80000003`)。一个都没有时会打印安装提示并以退出码 2 结束。

**字体栈与回退**(`tokens.css`):
- `--font-title`: **ZCOOL KuaiLe**(站点本地 woff2,标题/站点名/加载层)→ 回退 `cursive` → `--font-sans`
- `--font-serif`: Noto Serif SC → Source Han Serif SC → 宋体 → SimSun
- `--font-sans`: Segoe UI → Roboto → Helvetica Neue → system-ui → 微软雅黑 → Noto Sans SC
- `--font-mono`: SF Mono → Cascadia Code → Fira Code → Consolas → 微软雅黑

**图标字体**:FontAwesome `fa-solid-900.woff2` 已按实际用到的图标子集化(1.8KB),新增图标类名时同样要重新子集化。
