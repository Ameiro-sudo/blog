## 1. 项目概览

零后端静态博客,单页 SPA,Markdown 写作,GitHub Pages 托管,Cloudflare CDN 加速。

- **渲染**:Vanilla JS SPA(hash 路由 `#/post-id`),markdown-it 14 + DOMPurify 3 + highlight.js,全部 vendor 本地化
- **构建**:Node 脚本 `scripts/build.js`,生成文章索引 / RSS / sitemap / 版本 hash
- **部署**:GitHub Actions 自动构建 → 推 `gh-pages` 分支 → GitHub Pages(源已切换为 gh-pages 分支)
- **零外部运行时依赖**:JS/CSS/字体/图标全部在仓库内(唯一外部资源是 GitHub 头像 CDN)

## 3. 构建系统

`npm run build` → `node scripts/build.js`,做以下事情:

1. **文章索引**:解析 `content/posts/*.md` 的 front matter(YAML)→ 生成 `content/posts/index.json`(id/标题/日期/标签/置顶/封面/摘要)
2. **相册索引**:自动扫描本地 `assets/vendor/images/albums/` 平铺图片生成 `content/albums/index.json`(单相册,封面取第一张,EXIF 自动读取);可选 `meta.json`(title/description/date)放在该目录下控制相册元数据。预留远程接入接口:在 `site.config.json` 配置 `albumsSource`(远程 JSON 地址)后,构建改为从该地址拉取相册数据
3. **RSS / sitemap**:从索引生成 `feed.xml`、`sitemap.xml`
4. **版本 hash**:拼接 CSS/JS 源文件算 MD5,写入 `index.html` 的 `?v=` 参数;内容变化时更新 `build-ts`
5. **配置注入**:读取 `site.config.json`(SITE_URL/CDN_BASE/profile/ogDefaults),构建时注入 `app.js` 的 `app.config`

**幂等**:内容无变化时不会改文件(build-ts 不 bump),CI 里 `git diff` 无变更则不会产生构建提交。

**站点配置**:改头像/昵称/链接/站点地址等只需编辑 `site.config.json`,再 `npm run build`,不要直接改 `assets/js/snowblock.js`(该文件里的 `app.config` 是空占位,内容由构建注入)。

**Windows 注意事项**:
- 构建在 Linux(CI)与 Windows(本地)的行尾/路径行为不同;`build.js` 已用 `path.basename()` 修复 Windows 路径 bug
- 本地 build 产物 hash 与 CI 不同是正常的(CRLF vs LF)

## 4. CI/CD 流程(`.github/workflows/ci.yml`)

触发:push 到 main、PR、手动 dispatch。

步骤:
1. Checkout
2. Setup Node(node 版本读 `.nvmrc` = 22,npm 缓存)
3. `npm ci`
4. `node scripts/build.js`
5. **部署**:`peaceiris/actions-gh-pages@v4`,`force_orphan: true` 推 gh-pages 分支;`exclude_assets` 排除开发文件(scripts/package.json/lighthouserc/deploy.sh 等)
7. **Lighthouse**:`lhci collect` 本地静态产物生成报告(纯报告,**无断言不阻塞**),`upload-artifact` 上传(注意 `include-hidden-files: true`,因为 `.lighthouseci` 是隐藏目录)

**部署拓扑**:
```
push main → CI 构建 → force push gh-pages → GitHub Pages(源 = gh-pages) → CF 缓存
```

**GitHub Pages 配置**:仓库 Settings → Pages → Source: **Deploy from a branch → gh-pages / /(root)**。不要改回 main。

**CI 踩坑史**(勿回退):
- Lighthouse 断言(preset error 级 color-contrast 等)曾导致 CI 频繁失败 → 已改为纯 collect 无断言
- `lhci upload`(filesystem)会清空 collect 临时目录 → 只用 collect
- upload-artifact 默认忽略隐藏目录 → 必须 `include-hidden-files: true`
- 直接 `git push HEAD:gh-pages` 权限问题 → 改用 peaceiris action

## 5. 文章写作

文件:`content/posts/postN.md`(新建请用 `post8.md` 递增命名)。

Front matter 格式(注意:**标题用 `# ` 一级标题写在文件首行**,build.js 和前端 stripFrontMatter 都依赖它):

```markdown
# 文章标题
date: 2026-08-05
tags: 标签1, 标签2
time: 21:00
readTime: 8 分钟
pinned: false
image: assets/vendor/images/posts/cover-xxx.webp   # 可选,封面图
---

正文 markdown...
```

**发布流程**:
1. 写文章 md
2. 本地 `npm run build` 验证索引正常
3. `git add` 文章 + 构建产物,`git commit`,`git push` — CI 自动部署
4. 线上约 2-3 分钟生效(CF 缓存 HTML 为 DYNAMIC 不缓存,静态资源带 ?v= hash)

**文章内容规范**:
- 图片放 `assets/vendor/images/posts/`,正文用相对路径 `assets/...`(init.js 的 mdImage 规则会保留此类相对图片)
- 新增汉字后**需重新子集化字体**(见 §8),否则新字会缺失

## 6. 图片管理规范(重要!)

**封面图**(`assets/vendor/images/posts/`)与**相册图**(`assets/vendor/images/albums/`)遵循以下规则:

- **图片由本人(Ameiro-sudo)亲自提交** — 图片曾被提交进历史,已通过 `git filter-branch` 重写历史清除旧版本;重新提交时保持图片所在的独立提交即可
- 修改引用方式:
  - 文章封面:编辑 `content/posts/xxx.md` 的 `image:` 字段
  - 相册:直接把图片放入 `assets/vendor/images/albums/`(平铺),构建自动生成索引(见 §7)
- 图片规范:封面 600px 宽 webp 质量 80;相册 500px 宽(2026-08-05 性能优化后标准)
- 已提交记录:`dde6dc5`(封面+相册)、`f14e290`(缩小优化)

**⚠️ 性能优化提示**:CI 构建从 git 拉代码,图片必须在仓库内(已满足);若以后图片要移出 git,需改用图床托管。

## 7. 相册管理

**相册索引由构建自动生成**:`node scripts/build.js` 会扫描 `assets/vendor/images/albums/` 下所有图片,生成 `content/albums/index.json`(单相册,封面取第一张,自动读取 EXIF)。

- 新增相册图:直接把图片放进 `assets/vendor/images/albums/`(支持 jpg/jpeg/png/webp/gif/bmp),再跑一次构建
- 删除图片:从目录删除即可,构建会自动更新索引(不会残留失效引用)
- 相册元数据:在该目录放 `meta.json` 控制标题/描述/日期:
  ```json
  { "title": "照片墙", "description": "", "date": "2026.08" }
  ```
- 前端兼容空数组(显示"暂无照片")

## 8. 字体子集化

`assets/vendor/fonts/files/ZCOOL_KuaiLe.woff2`(92KB)是全站文本的子集。**新增文章出现新汉字时,必须重新子集化**,否则该字不显示。

工具(临时目录,已装):`%TEMP%\opencode\fonttools`(subset-font 2.5 + sharp)
脚本:`%TEMP%\opencode\subset-font.js` — 收集全站 md/json/js/css/html 文本 → 子集化 → 覆盖 woff2。

**字体栈与回退**(`tokens.css`):
- `--font-title`: **ZCOOL KuaiLe**(站点本地 woff2,标题/logo)→ 回退 `--font-sans`
- `--font-serif`: Noto Serif SC → Source Han Serif SC → 宋体 → SimSun
- `--font-sans`: Segoe UI → Roboto → Helvetica Neue → system-ui → 微软雅黑 → Noto Sans SC
- `--font-mono`: SF Mono → Cascadia Code → Fira Code → Consolas → 微软雅黑

Windows 实测:Noto Serif/Sans SC、微软雅黑、宋体、黑体、楷体、Segoe UI、Consolas 均可用;SF Mono / Fira Code / PingFang / Roboto / Source Han 未装(栈中靠后的回退项,有前面字体兜底,不会显示异常)。

## 9. 行尾与编码规范(踩坑记录)

- **`.gitattributes`**:`* text=auto` + `*.md/js/css/html/json/xml/yml/sh/ps1/cjs text eol=lf` — 仓库内统一 LF,任何平台检出 LF,已重新规范化过历史
- **不要**把文件改成 CRLF 提交;`\r` 曾导致 `stripFrontMatter` 正则失效(文章页顶部显示元数据)
- 所有内容文件必须 **UTF-8**(无 BOM)
